# ADR-0005: 条件化思考路由

- **状态**：已采纳
- **日期**：2026-09-18
- **决策者**：@231dff

## 背景

kimi-k3、deepseek-reasoner 等思考模型对所有问题都生成冗长思维链。
简单任务（"读一下 README"）也要 16 秒。

实测数据：
- 简单任务：16s（其中 ~12s 是 thinking）
- 复杂任务：15s（thinking 有价值）

## 决策

**规则路由**，按任务复杂度决定是否开思考。
任务文本
↓

strategy 强制覆盖（always / never）
↓

多子问题（"先X、再看Y、最后跑Z"）→ 开
↓

强关词命中（"读一下"、"看看"）→ 关
↓

强开词命中（"为什么"、"设计"）→ 开
↓

长度启发（<30 字符关，>200 字符开）
↓

默认保守：开


Provider 适配：
- moonshot / qwen 系列：`extra_body` 传 `thinking` 开关
- anthropic：`thinking` budget
- 兜底：system prompt 注入 `[模式: NoThinking]`

## 理由

### 为什么用规则而非 LLM 路由器？

- **零延迟**：规则匹配 <1ms
- **零成本**：不调用 LLM
- **可解释**：每条判断有明确理由
- **够用**：实测准确率 >85%

LLM 路由器会引入 200-500ms 额外延迟，投入产出比不划算。

### 为什么放在中间件链最前？

ThinkingRouter 读的是**用户的原始输入**，不希望被压缩/改写。

### 为什么默认保守开？

- 误判开：浪费 token 但质量不变
- 误判关：**严重**，简单任务变差

宁可保守。

## 后果

### 正面
- 简单任务延迟 16s → 4.2s
- 复杂任务质量不变
- 环境变量可调（`AGENT_THINKING_STRATEGY`）

### 负面
- 关键词表需要维护
- 中文边界情况（"帮我看看这个报错"）需人工判断

### 升级路径
如果准确率 < 70%，可以上 LLM 路由器兜底。
现阶段不需要。
